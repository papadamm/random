# ssd1306-hex-display-rtt-v5 (HL GPIO sequencer test code)

Based on parts of HL 9d9bba4, this directory contains some GPIO sequencer test code, pretty much enough to drive the SCL and SDA signals connected to the ssd1306 display controller. Also RTT is included to provide means for debug output over the JTAG in case further debugging would be needed. For instructions on how to program the target please see teeensy-pixhawk-6c-stm32h743.sh also the actual source code contains definitions on how to use RTT and how the SCL and SDA signals should be connected. The power for the LCD module comes from the GPS1 port of the pixhawk 6c.

In case you would like to change target system to a different microcontroller or SoC, one thing to look out for would be how be how to handle the pull-up resistors for the SCL and SDA signals. The protocol requires the pins to be pulled high when the bus is idle, and using external resistors and Input (Hi-Z) or Open Drain outputs would one obvious way to go, or if you have a device with a GPIO/PINMUX that has on-chip resistors it is probably possible to use those. However this varies quite much from vendor to vendor (ATMEGA328P requires special sequence to transition between pulled-up input to output in certain cases to avoid glitches) and also within vendor (STM32F1 has an older type of GPIO where pull-ups cannot be enabled for outputs while STM32H7 has a more modern GPIO where pull-ups may be enabled both for input and output).

To study the protocol waveform and look for glitches a tool like Saleae Logic is extremely helpful, however beware that the output and accuracy of this tool sometimes is highly weather dependent. It is hard to know when it is correct and when it is not. This comment is about the Logic2 app on Mac OS X by the way.
